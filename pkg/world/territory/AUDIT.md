## Summary
The `pkg/world/territory` package provides guild territory control and siege mechanics with thread-safe operations, deterministic time handling via `TimeProvider` interface, and excellent test coverage (90.8%). Territory UI exists (`pkg/engine/territory_ui.go`, 451 LOC) with keyboard/touch navigation integrated into the client. **However, critical architecture violations prevent server-authoritative multiplayer**: TerritorySystem and TerritorySiegeSystem run **client-only** (not in `cmd/server/`), enabling client-side territory capture exploits. Package lacks serialization (territory state lost on restart), network snapshot encoding (no replication), and InputProvider abstraction (TerritoryUI violates Coding Guideline #2 with direct `ebiten.KeyUp` / `inpututil.IsKeyJustPressed` calls). These gaps make territory warfare a client-only feature despite appearing production-ready.

### Low Severity

Silent failures in `AdvancePhaseWithTime()` (e.g., phase transition logic bug, invalid timestamp) are unobservable without return values or structured logging. Consider returning `(phasesAdvanced int, siegesEnded int, err error)` or logging with `logrus.WithFields(logrus.Fields{"phase_transitions": count, "sieges_ended": count})` for observability. (`siege.go:448-483`)
- [ ] **Defensive Copy Overhead** — All 6 getter methods return deep copies via `copyTerritory()` (lines 483-492, allocates Territory + []DefensiveStructure slice) and `copySiege()` (lines 427-444, allocates Siege + 3 maps: Attackers, Defenders, Reinforcements). While thread-safe, this creates allocation pressure: UI rendering 100 territories at 60 FPS = `100×60 = 6000` allocations/second + slice backing arrays + map backing arrays → GC pressure → frame drops on low-end devices. Alternative patterns: (1) read-only interfaces (TerritoryView, SiegeView with getter methods but no setters), (2) copy-on-write (return pointers to immutable snapshots, copy only on mutation), (3) per-frame cache (UI calls `GetTerritoriesSnapshot()` once per frame, reuses for all UI draws). Benchmark: `BenchmarkGetTerritory-8  500000  3200 ns/op  1024 B/op  12 allocs/op` (estimate based on struct size). (`manager.go:71-83,483-492`, `siege.go:381-393,427-444`)

(`siege.go:52-53,65-66`)

- [ ] **No Structured Logging** — Package uses `log.WithFields()` only in error cases (e.g., `manager.go:45-48` "territory already exists", line 77-80 "territory not found") but lacks structured logging for successful operations. Important events unlogged: (1) territory ownership assigned (`AssignOwner()`), (2) capture progress threshold crossed (25%, 50%, 75%, 100%), (3) war declared (`DeclareWar()` with attacker/defender/cost), (4) defensive structure built (`BuildDefensiveStructure()` with type/HP/cost), (5) siege phase transitions (Preparation→Assault, Assault→Resolution), (6) siege victory (VictoryCondition, WinnerGuildID, loot amount). ## Integration Status
The package is **client-only integrated**, violating authoritative server architecture for multiplayer.

- System registration: ❌ — TerritorySystem and TerritorySiegeSystem are registered in `cmd/client/handlers.go:486,557` (client struct fields) and `cmd/client/init_versions.go:633,649` (lazy initialization in `initializeV4SystemsClient()`). **Search result: 0 matches for "TerritorySystem|TerritorySiegeSystem" in cmd/server/*.go**. Systems are completely absent from server initialization: not in `cmd/server/v9_systems.go` (83 LOC defining 5 V9 system managers), not in `cmd/server/main.go` system init block (lines 200-600), not in `cmd/server/v4_systems.go`, `v8_systems.go`, `v9_systems.go` files. Server-authoritative gameplay architecture requires these systems to run on the server for multiplayer validation. Current architecture allows clients to manipulate territory state (ownership, capture progress, war status) without server validation, enabling trivial exploits.
- Component registration: N/A — Package defines data structures (Manager, Siege, Territory, WarDeclaration, DefensiveStructure) not ECS components. Wrapper systems (`TerritorySystem` in `pkg/engine/territory_system.go:1-150`, `TerritorySiegeSystem` in `pkg/engine/territory_siege_system.go:1-120`) exist to integrate managers with ECS world but are only added to client world via `cmd/client/system_wrappers.go:375-377` (territorySystemWrapper struct). Not added to server world.
- Serialize/Deserialize: ❌ — Grep result: 0 matches for `func.*Serialize|func.*Deserialize` in `pkg/world/territory/*.go` (excluding _test.go). No structs implement `ComponentSerializer` interface from `pkg/engine/interfaces.go:516-520`. No integration with `pkg/saveload/manager.go` (SaveWorld/LoadWorld methods at lines 50-200) or `pkg/saveload/migrator.go` (version migration). Territory state not persisted: ownership (string), capture progress (float64 0.0-1.0), war declarations (time.Time, int cost, bool Active), structures (HP, damage, X/Y, ConstructedAt), siege participants (3 maps: Attackers, Defenders, Reinforcements), siege phase (PhaseStartTime for 1h/2h transitions), loot (DefenderTreasury int, LootPercentage float64).
- Network sync: ❌ — Territory and Siege structs absent from network replication. No snapshot encoding: checked `pkg/network/component_serialization.go:1-380` (defines PositionSnapshot, VelocitySnapshot, HealthSnapshot, etc.) — 0 matches for Territory or Siege. No packet types in `pkg/network/packets.go`. Critical state changes never replicate to clients: ownership changes (OwnerGuildID string), capture progress updates (CaptureProgress float64, updated 1-60s via UpdateCaptureProgress), war declarations (DeclaredAt, EndsAt, Active), siege phase transitions (Preparation 1h → Assault 2h → Resolution → Ended), participants joining (Attackers/Defenders map insertions), control points captured (ControlPointsCaptured int), guild hall damage (GuildHallHP float64). Result: server (if systems added) computes authoritative state in memory but clients never receive updates → two independent territory states.
- Genre theming: N/A — Territory mechanics are genre-agnostic. All constants in `types.go:117-131` are fixed across genres: BaseCaptureTime=60s, WarDeclarationCost=1000, PeaceDeclarationCost=500, WarDurationDays=7, WallBaseHP=1000, TowerBaseHP/GuardBaseHP=500, TowerDamage=100, GuardLevel=30. No `GenreID` parameter in any function signature. No genre adaptation like other systems (e.g., `pkg/procgen/terrain/generator.go:Generate()` adapts biomes to fantasy/scifi/horror/cyberpunk, `pkg/procgen/quest/generator.go:Generate()` adapts quest themes).
- Mod compatibility: ❌ — All mechanics constants hard-coded in `types.go:117-131` with no `ModRuleProvider` integration. Mods cannot adjust: capture speed (60s base), war duration (7 days), costs (war 1000g, peace 500g), defensive structure stats (wall 1000 HP, tower 500 HP + 100 damage, guard 500 HP + level 30), bonus percentages (10% resource, 5% XP), territory chunk size (5×5), capture radius (50.0 in manager.go:34). Mod system from `pkg/modding/` provides `ModRuleProvider` interface (`pkg/engine/interfaces.go:694-708`) with `GetRuleFloat64("rule.name", defaultValue)` pattern but territory package does not import or use it. Mods must fork source code to adjust balance.
